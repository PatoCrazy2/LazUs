## 1. Executive Product Identity & Non-Negotiables

LazUs is an intimate, mobile-first Progressive Web App (PWA) designed exclusively for two paired partners. It is **not** a dating app, social network, or public feed.

### Core Architectural Invariants
1. **Never introduce Next.js, Express, NestJS, or FastAPI.**  
   The application is strictly a **React + Vite SPA** deployed alongside a **Hono API** in **Cloudflare Workers**. Do not propose migrating to SSR frameworks.
2. **Data Authority Rule:**  
   - **Dexie (IndexedDB):** Client-side speed, optimistic UX, offline cache, and Outbox queue. **Never** trust IndexedDB for authorization, pairing validation, or permission checks.
   - **PostgreSQL (Neon via Hyperdrive):** Single source of truth for all business decisions, permissions, and reveal unlocks.
3. **Zero-Leak Blind Reveal:**  
   A partner must **never** see the other's submission until both have completed their answer for the daily activity.  
   - The server **must never** return the partner's submission content (in HTTP responses or WebSocket messages) until `status === 'revealed'`.
   - Never filter secrets on the client side. The SQL/API layer must physically omit the partner's text/photo before reveal.
4. **Offline-First & Idempotency:**  
   The app must function offline. Every state-mutating operation generated by the client must assign a stable `client_mutation_id` (UUIDv4) and use the local **Outbox pattern**. The backend must track idempotency in an `idempotency_keys` table.
5. **Realtime via Durable Objects with WebSocket Hibernation:**  
   Realtime couple communication is handled by Cloudflare Durable Objects (1 DO instance per `couple_id`).  
   - **Mandatory:** Always use Cloudflare's **WebSocket Hibernation API** to keep memory/compute within the **$0/month free tier**.  
   - DOs handle ephemeral presence and low-latency signals (`partner_completed`, `affection_received`), but **never** act as the permanent database.
6. **Zero-Egress Private Media (Cloudflare R2):**  
   Never proxy large media uploads through Hono/Workers. Use short-lived presigned URLs for direct client uploads to R2.  
   - R2 buckets must **never** be public. Media is accessed via short-lived signed URLs or authenticated edge routes.
7. **NFC Operating Principle:**  
   Physical NFC tags/bracelets store standard HTTPS URLs (`https://app.example.com/tap/<tag-id>`).  
   - **Zero dependency on Web NFC API** (due to iOS Safari incompatibility). Routing is handled by the OS opening the PWA deep link.
8. **Vertical Slice / Feature Architecture:**  
   Code is organized by domain features (`features/<feature-name>`). Features must never import internal components from other features. Shared contracts, Zod schemas, and types reside in `shared/`.
9. **Strict Package Manager (`pnpm`):**  
   Always use **pnpm** exclusively (`pnpm install`, `pnpm add`, `pnpm run`). Never use `npm` or `yarn`. Enforce strict dependency resolution and monorepo/package integrity.

## 4. Production Engineering Standards

### PWA Mobile Resilience
- Request persistent storage upon app initialization: `navigator.storage.persist()`.
- Detect standalone mode (`display-mode: standalone`). Web Push on iOS requires standalone installation (Home Screen). Guide the user before requesting push permission.
- Handle `visibilitychange`: when returning from background, ping the server/DO to reconcile stale socket connections.

### Outbox & Error Handling
- Network/5xx errors: Reattempt with exponential backoff and jitter.
- 4xx errors (client/business errors): Do not loop indefinitely. Route to Dead-Letter Queue (DLQ) in Dexie and flag UI.

### Observability & Privacy
- Never log user answers, prompts, photos, auth tokens, or cookies.
- Logs must contain only technical metadata: `couple_id`, `activity_id`, `status_code`, `latency_ms`.
